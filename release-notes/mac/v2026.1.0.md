# Mac 2026.1.0

## New

- Terminal panes draw faster: lines are laid out once and kept as they scroll, so scrolling colourful output is three to five times cheaper to draw, and a flood of output almost twice as cheap.
- Terminal panes draw with Metal: big panes and busy output stay smooth, and a flood of output into a full-screen pane on a large display shows about four times as many frames a second. To go back to the previous renderer, set terminal-renderer = coretext in the config file.
- Typing in a terminal pane redraws only the line you're on, not the whole pane: much lighter when the screen is full of colour, like a coding agent or an editor.
- Copy Session Link (⌥⌘C, in the Pane menu, the command palette and a pane's or tab's menu) copies a Claude Code session's Remote Control link, to open it on claude.ai or your phone. `hmk session-link` prints it, and the TUI's menus have it too.
- Find Next and Find Previous are in the command palette, for browser and editor panes.

## Fixed

- A faint line no longer comes and goes under a powerline prompt as you type below it.
- Terminals keep up better with a flood of output, like a big file printed or a noisy build.
- A config file created by Hammock's server, rather than the app, lists the newer settings too, such as group-headings, remote-network and usage-live.
- A message sent in the agent view while Hammock is reconnecting is put back in the box instead of being lost.
- A pane's saved screen no longer comes back after the pane closes, and a crash while saving it can no longer make a reopened terminal show output twice.
- A pane whose command had already finished no longer runs it again when you log back in or restart, so kept scheduled-command runs aren't repeated outside their schedule.
- A scheduled command that finishes while Hammock is updating or restarting is now recorded as done, rather than staying "running" and skipping every later run.
- A terminal opened just before Hammock's background service restarted comes back working, instead of failing to start with "address already in use" or "file exists".
- A terminal that can't be started again after Hammock restarts now says why in red, instead of showing a blank pane.
- After reconnecting to the Mac, if the tab you were on has gone, you land on the tab beside it rather than the first tab.
- An agent asking to write a very large file now shows that it needs you, instead of the request going unnoticed.
- Bigger and Smaller keep terminal text between 6 and 72pt, so after shrinking it as far as it goes, Bigger works again straight away.
- Cursor blink, the terminal font, line spacing, Thicken text and paste protection can now be set back to Hammock's default when your Ghostty config sets them, instead of springing back to Ghostty's value.
- Delete Group now asks first when an agent in it is working or a file has unsaved changes, and selects the Group next to it, as ⌘W does.
- hmk approve now refuses a role other than drive, view or decline, instead of turning the request down.
- hmk audit with a number below 1 (hmk audit -5) says how to use it instead of crashing.
- hmk ls and hmk computers line their columns up when names have Chinese, Japanese or Korean characters or emoji in them.
- hmk schedule add --command keeps your quoting: -- sh -c 'echo a; date' runs that, rather than losing the quotes.
- hmk schedule add with --days but no --at asks for a time, instead of making a schedule that runs at midnight.
- hmk send with --key but no key name after it says so, instead of typing "--key" into the pane.
- hmk tui: a scheduled task's When of only day names, like “mon tue wed thu fri”, now asks what time it runs instead of being saved as a cron line that runs at the wrong times.
- hmk tui: a long path or address typed into a dialog's field now scrolls to keep the cursor and the end of the text in view.
- hmk tui: moving the mouse no longer sometimes types stray text like <35;20;10M into the focused pane.
- hmk tui: with Horizontal Tabs, tabs in the tab bar can now be dragged to reorder them, as Help says (or onto a Group in the sidebar to move them there).
- Holding a key (like Delete) while sharing a Mac's screen now repeats it, from an iPhone or iPad keyboard too.
- Images a program shows by file path, like Claude Code's, now show on your iPhone, linked computers and in shared Groups too. Hammock only reads files that are images, so the Show images from file paths setting is gone.
- Images in the terminal, like Claude Code's, no longer go missing when you open the pane on another device, resize it or reconnect.
- In the agent view, a command's output that arrives after you've sent a new message from an earlier point no longer replaces your first message.
- In the agent view, a file an agent writes no longer shows one line more than it has, or a blank added line at the end.
- In the agent view, a message you send that starts with a tag, like "<Button> renders twice", no longer disappears from the conversation.
- Moving a tab to another Group no longer leaves the Group it came from named after, and starting agents in, the tab that moved.
- Needs You keeps what's waiting for you when Hammock's background service restarts, such as after an update, instead of coming back empty.
- Panes side by side stay in place when one has a long title, such as a long command: the title shortens instead of pushing the panes beside it out of line.
- Pasting, or sending with hmk send, more than 4 MB into a terminal now arrives in full instead of being silently dropped.
- Previous Pane and Next Pane (⌘[ and ⌘]) no longer get stuck on a browser pane. Go back and forward in a browser pane with ⌘← and ⌘→ instead.
- Removing a shortcut in Settings ▸ Keyboard now sticks when another kind of pane uses the same one (an editor's Save and a simulator's Screenshot to File, both ⌘S).
- Scrolling a picture shown in a terminal back into view no longer stutters.
- Searching Settings for an editor setting (wrapping, line numbers, indentation, tab width, font size, Vim keys) jumps to it.
- Simulator panes take taps and typing again after the simulator restarts outside Hammock, from Xcode, say, rather than ignoring them until the pane is reopened.
- Terminals keep 10,000 lines of scrollback, as the Mac's daemon does: coloured output kept only a few hundred.
- The agent view no longer goes blank in a long conversation, showing only Working… under an empty screen, when you open it or send a message.
- The agent view no longer shows stray escape codes, such as links and window titles, in a command's output.
- The agent view no longer stops updating when a long tool output is cut off in the middle of an emoji or other non-ASCII character.
- Turning a log pane into a browser, simulator or editor now stops reading its log and deletes the entries it kept.
- With an empty Group selected, pane commands (split, Close Pane, ⌘W) no longer act on a pane in the tab you just left.
- With the sidebar showing one computer's Groups, closing the Group you're on selects another Group it shows, not one on a computer it's hiding.

## Internal

- Metal renderer: Kitty images, IME text being composed, font-thicken and debug snapshots, matching CoreText (#18, phase 3).
- Renderer benchmark: just render-bench times the Mac terminal's drawing offscreen, and HMK_DEBUG_RENDER_STATS times real draws and output parsing (#18).
- TerminalMetalRenderer draws terminal panes with Metal: a glyph atlas and one instanced draw per frame (terminal-renderer, metal by default; #18).
- Daemon: a log pane's entries (panelogs/<pane id>.jsonl, and its .tmp) left by a pane that's gone are pruned at startup, as holder logs and saved screens are.
- Daemon: a pane's holder log (logs/holder-<id>.log) goes when the pane closes for good, and those of gone panes are pruned at startup.
- Debug snapshots draw Metal panes with Metal (read back from an offscreen frame), not CoreGraphics.
- HammockKit: the remote (iPhone) link is pinged when its network changes or the app comes back, and redialled if it doesn't answer. The Mac's local socket isn't affected.
- Versions are now YYYY.N.P, one per app: joint releases at YYYY.N.0, Mac patches in between, iPhone builds under its YYYY.N.0.
